# Pure Math Survey

**Software 2.1.0; knowledge/snapshot schema 2.0.0; output/policy-review schema 2.2.0; r3 policy `four-modes-2026-10-12-r3`.** These identities are distinct. Formal tag/Release publication remains paused. Local files, one integration writer, Python 3.10+. Mathematics and manuscripts are English; discussion follows the user's language.

## Own the request and actual project

Act as the daily-use main responsible for the full user scope, integration and final conclusions. This mathematical task differs from a main developing the skill software. Recover actual materials, reader operations, latest corrections, profile/view and deliverables; save the fixed revision (commit or file hashes), read/write boundaries and remaining work in existing notes. Clarify only missing choices materially changing scope; ordinary authorized work needs no repeated approval.

Knowledge-only/update-only requests end with usable knowledge, evidence and optional snapshots: **no new manuscript, article prepare or PDF**. When an article is requested without a profile, use **minimal + integrated** and produce only requested modes. Preserve every explicit topic branch and its promised depth. The seven-branch comparison regression is representative, never a compulsory topic or permission to narrow the user's request.

Read [architecture and daily-use coordination](references/architecture.md) for bounded delegation, actual dispatch/wait/acceptance, serial fallback, conflicts, stop/recovery and late results. Use available tools and authorized isolated candidates; main alone integrates the live KB. Record real task IDs/states, inspect returned files and reject obsolete revisions. Without delegation tools work serially and label roles honestly. Save evidence that permits recovery without chat access; do not invent a resident scheduler or database.

## Build source-grounded, understandable knowledge

For new projects use `python scripts/survey.py init --output PROJECT --topic SLUG --scope SCOPE.md`. Read [contracts](references/contracts.md) before adopting policy; preserve historical bytes and reject unknown/mixed schema-policy combinations.

Read [problem formulation](references/problem-formulation.md), [research/evidence](references/research-and-evidence.md) and [core problems](references/core-problems.md). Fix objects, data/unknowns, ordered quantifiers, variations and exclusions in scope and nodes. Search primary formulations, alternatives, counterexamples and follow-ups; actually read relevant original sections at their controlling version/locators. Record queries, candidates, exclusions, omission challenge, stopping reason and unread scope. Abstracts are discovery clues. A preprint remains a preprint unless publication metadata is checked; do not resolve a version conflict by choosing the latest year. Never hash notes as original bytes or redistribute private/source material merely because it was readable.

Read [reader calibration](references/reader-calibration.md), [overview](references/overview.md) and [proof responsibility](references/proofs-and-boundaries.md). Default to undergraduate general plus relevant early doctoral operations, not every field's prerequisites. Classify inputs for this reader × goal × use as Assumed, Refreshable or Bridge-required. Recognizing, applying and proving differ; establish unfamiliar constructions before first use.

The **KB itself**, even without an article, needs usable fast routes and reproducible slow explanations. Overview, problem routes and nodes are three reading scales, not three compulsory file trees. Fast passages expose objects, inputs, decisive construction, why it suffices, indispensable conditions and precise entrances into detail. Slow passages perform promised constructions/calculations, exact imported-theorem applications, endpoints, constants and limit checks. Each nontrivial fast arrow links a specific slow subsection; that subsection identifies its route, output and consumer. Check both directions. Node lists or “details in KB” do not deliver this.

Keep one canonical authority: formal definitions/results/relations use one label-free `## Canonical statement` with one `latex` block containing all hypotheses, quantifiers and conclusions. Nodes own facts; overview/routes explain; manuscripts own wrappers and reading order. Facets overlap, rather than creating four databases. Navigation edges do not prove implications. New comparisons/deductions require actual reviewed node arguments. New reusable explanations also return to the live KB; review, freeze a new snapshot and explicitly adopt it downstream. Never edit frozen bytes or generated fragments.

## Review obligations before locating them

Read [validation](references/validation.md) and [output review](references/output-review.md). Reconstruct necessary proof/learning obligations from the exact target, reader baseline and mathematics **before** comparing the author's list or locating its entries. Look for missing object identifications, normalization, singular starts, limit topology, regularity and present applications of imported results. Deep theorems may be imported exactly; current substitutions, hypothesis checks and decisive object conversions still require explanation.

Hide long proof interiors and reconstruct the fast route; perform a concrete slow step from declared inputs; change a decisive condition and locate the first failure. Save actual answers/derivations, failures, repairs and unchecked scope. Failure of one proof route alone is not a counterexample. Knowledge-only findings bind existing knowledge-review scope/findings to node/route revisions, hashes and subsections; do not fabricate manuscript locations. Article r3 mode findings add obligation_coverage, fast_route_reconstruction, slow_step_reproduction and condition_transfer using existing outcome/finding/locations. Software shape/binding checks cannot judge sufficiency.

`kb validate PROJECT` checks structure. `kb readiness PROJECT --plan PLAN` checks selected scope, closure, sources and promises; accepted fields/source counts do not establish understanding. Keep mathematical, publication, evidence and selection states distinct. Unassessed is not open: openness requires a precise target and dated follow-up searches. Read [records and delivery](references/records-and-delivery.md) for the actual evidence locations. Templates remain pending until actual work. Use `author_reread` for the author's/agent's reading. Other AI tasks may find errors; they do not establish external independent review or real-reader learning.

## Freeze, design and write only requested outputs

`kb freeze PROJECT` fixes immutable bytes, even before readiness; freezing grants no readiness. `kb diff PROJECT --from OLD --to NEW` reports changed knowledge/consumers. Create `output plan PROJECT --output ID --snapshot KB-...` and refine audience, goals, selections, exact proof/import promises and omissions. Read [selection](references/length-and-selection.md) and [profiles](references/editions.md). Overview maps project routes; output outline answers this article's target, audience, principals, points, connections and limits. Use existing plan/outline fields, not an invented API.

`output prepare PROJECT --plan PROJECT/outputs/ID/plan.json` produces exact fragments/materials and an unfinished scaffold. Inspect `artifacts.exposition_design`; knowledge readiness never requires an article outline. Complete topic-specific outline and prose. Reprepare preserves authored main, outline and style. Explicit draft preview remains visibly unverified and retains canonical/material/TeX safety. Missing, extra or changed materials are errors; editable notes belong outside materials.

Read [introduction](references/introduction.md) and [writing style](references/writing-style.md). Every principal keeps its complete canonical input in a suitable result environment, nearby indispensable definitions and an isolated full-statement reading. Fix canonical deficiencies in the KB before freezing again. Surrounding prose may not strengthen quantifiers, strictness, ranges or status.

Under **r3**, Minimal defaults to local problem units: a short result map, each complete result near its required points, decisive connections and first use/boundary. Shared constructions have one authority and precise reminders at reuse. No fixed chapter count or mandatory three labels. A suitable three-chapter design is legal with an outline reason and all r3 review responsibilities. Historical **r2/rc1 and rc2** retain exactly Main Results / Key Mathematical Ingredients / Connecting the Ingredients, with principals in the first numbered section, under their recorded policy.

Thematic organizes questions, actual approaches and supported synthesis on matching assumptions/quantifiers. Lecture develops every promised construction, estimate and limit from declared capabilities. Paper defaults prominently to **DRAFT_UNVERIFIED** and requires authorized contribution, explicit comparison pairs, primary support for closest prior results and complete original proofs. Retain F1 body locations, F2 view/design, F3 comparison/support and F4 incomplete-design safety. The five views integrated/foundations/results/methods/boundaries change actual reader work, never mode responsibilities or facts; changed view requires fresh reading.

Actively target **about 2–3 normal actual typeset lines** for ordinary explanatory prose in all modes. Longer blocks trigger editorial review for hidden objects, conditions and mathematical actions. Show useful equations, maps, estimates or transformations with nearby meaning; never add decorative formulas, force breaks, shrink type/margins, fragment proofs or omit hypotheses. Necessary complete statements/continuous proofs may exceed the target with a specific justified exception. Record actual PDF page/block, source location, finding, repair or considered alternatives, final PDF hash and reinspection scope. Source-line counts/formula quotas cannot certify readability.

## Build, inspect and report fixed evidence

Run `output validate PROJECT --output ID --stage structure`; actually reread each final TeX version and complete seven whole-manuscript checks plus located mode/principal/step findings. Ordinary findings must point to executed substantive body content, not comments, preamble, uncalled definitions or false branches. Exact bytes alone do not validate surrounding prose.

Run `output build PROJECT --output ID` then `output render PROJECT --output ID`; open **every actual page**. Rendering is not inspection. Repair, rebuild and refresh affected bindings. Preserve failed attempts and prior successful builds. Visual findings apply only to their fixed PDF/images; new pages need new observations and reused unchanged-page findings need verified image identity. Read [layout/build](references/layout-and-build.md).

Run `output validate PROJECT --output ID --stage release`. Only current-policy `RELEASABLE` outputs can use `output package PROJECT --output ID --to FILE.zip`; reopen the rebuildable archive. `--policy recorded` is read-only historical assessment, never current package authorization. Adopt r3 with a new output ID and actual new responsibility records; no silent migration of old snapshots, plans, accepted reviews or PDFs. Explicit `max_pages` is the only hard length gate.

Report software checks, source/mathematical reading, exposition task attempts, actual PDF inspection and real-reader feedback separately, with fixed hashes, failures and unverified scope. Real originality/full research-proof quality stays **NOT VERIFIED** without actual authorized original input and appropriate review. Software publication cannot change that. Use the [balanced dHYM reference](assets/reference-samples/dhym-balanced/README.md) and [example roles](references/exposition-examples.md) for local writing choices, never compulsory page/section counts or current acceptance.

For maintenance read [template maintenance](references/template-maintenance.md) and validate assets plus an isolated extracted installation. Survey has no Research Studio bridge, native Studio markers or resident multi-agent scheduler. Daily-use collaboration uses actual available tools and ordinary files with one integration writer.
