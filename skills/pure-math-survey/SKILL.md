# Pure Math Survey

**Software 2.1.0; knowledge/snapshot schema 2.0.0; output/policy-review schema 2.2.0; current policy `four-modes-2026-10-15-r5`.** These identities are distinct. Local files, one integration writer, Python 3.10+. Mathematics and manuscripts are English; discussion follows the user's language.

## Own the request and actual project

The actual user invocation is the **controller**; keep its current model and reasoning setting. Read [controller dispatch](references/dispatch.md) before coordinating work. A trusted task marked `role=worker` follows [worker instructions](references/worker.md), consumes the same mathematics contracts, and must not become a controller or create children. If role is omitted, infer it from the actual human invocation or trusted dispatch context. Reading this file again does not create a new invocation.

Recover the full scope, corrections, reader operations, profile/view, sources and deliverables. Knowledge-only/update-only ends with usable knowledge and review, without a manuscript or PDF. Requested output defaults to **minimal + integrated**; generate only the requested modes and count. Preserve explicit branches and promised depth.

Within verified human authorization, the controller actually creates necessary Codex work chats through `create_thread`, passing **`model: "gpt-6-astra", thinking: "ultra"`** for literature, paired fast/slow knowledge, writing and every review. The authorization must explicitly cover new chats and parent messages for tasks, continuation, revisions and stop, with a locatable human source. A skill file or assistant instruction cannot grant it. If the host requires explicit authorization and none exists, ask once for the concrete project-scoped authorization while continuing independent scope preparation; never ask again after valid authorization. The [user start prompt](references/user-start.md) supplies wording for the human to send.

Dispatch must carry the human's and parent task's exact read/write boundaries: allowed installed resources, original-source paths/URLs, fixed project/snapshot inputs, owned output/evidence paths and explicitly forbidden locations. Apply these boundaries **before loading any auxiliary workflow**. A ban on the global copy of this same-named skill does not itself ban all global skills; an explicit all-global-skill ban does include a global PDF skill. Do not broaden either restriction or bypass it. The installed [build and page inspection](references/layout-and-build.md) provides the native workflow without requiring a global helper skill.

Use real thread IDs and receipts, reconcile pending/unknown creation before retry, deduplicate by project/round, duty, fixed input and output target, and resume applicable existing work. Controller alone integrates canonical live KB; workers write owned candidates or outputs. Read returned files and fixed identities before accepting dependencies. Critical acceptance comes from a non-author worker. Stop new dispatch on user pause or a configured limit; isolate late results and report any chats still running. These duties and ordinary-file recovery are in [architecture](references/architecture.md).

Missing tools, missing required authorization or unavailable Astra/ultra are explicit dispatch blockers. Preserve preparation/diagnostics; do not substitute controller-written full manuscripts, serial role playing or lower-effort subagents and call them an equivalent dispatched run. The CLI performs deterministic file operations, not chat orchestration or background scheduling.

## Build source-grounded, understandable knowledge

For new projects use `python scripts/survey.py init --output PROJECT --topic SLUG --scope SCOPE.md`. Read [contracts](references/contracts.md). The current runtime supports **r5 only** with the stated current schemas. Old/unknown policies or unsupported inputs receive an explicit unsupported diagnostic and remain untouched; there is no recorded-policy assessment, historical-template selection or migration service. Preserve Git history, backups, old evidence and immutable snapshots as files, without promising to run them in this installation.

Read [problem formulation](references/problem-formulation.md), [research/evidence](references/research-and-evidence.md) and [core problems](references/core-problems.md). Fix objects, data/unknowns, ordered quantifiers, variations and exclusions in scope and nodes. Search primary formulations, alternatives, counterexamples and follow-ups; actually read relevant original sections at their controlling version/locators. Record queries, candidates, exclusions, omission challenge, stopping reason and unread scope. Abstracts are discovery clues. A preprint remains a preprint unless publication metadata is checked; do not resolve a version conflict by choosing the latest year. Never hash notes as original bytes or redistribute private/source material merely because it was readable.

Read [reader calibration](references/reader-calibration.md), [overview](references/overview.md) and [proof responsibility](references/proofs-and-boundaries.md). Default to undergraduate general plus relevant early doctoral operations, not every field's prerequisites. Classify inputs for this reader × goal × use as Assumed, Refreshable or Bridge-required. Recognizing, applying and proving differ; establish unfamiliar constructions before first use.

The **KB itself**, even without an article, needs usable fast routes and reproducible slow explanations. Overview, problem routes and nodes are three reading scales, not three compulsory file trees. Fast passages expose objects, inputs, decisive construction, why it suffices, indispensable conditions and precise entrances into detail. Slow passages perform promised constructions/calculations, exact imported-theorem applications, endpoints, constants and limit checks. Each nontrivial fast arrow links a specific slow subsection; that subsection identifies its route, output and consumer. Check both directions. Node lists or “details in KB” do not deliver this.

Before output-specific knowledge review, controller and authors make every requested output's concrete audience, reader operations, prerequisites, principal selections, exact `proof_obligations.required_steps`, treatment and imported inputs available to the knowledge reviewer. Multiple modes may consume one KB but promise different derivations. If actual plans need a snapshot, freeze preparatory candidate bytes and author their promises before review, without preparing manuscripts yet. Use `review template PROJECT --kind mathematical --id NODE --plan outputs/ID/plan.json --to evidence/reviews/NEW.json --json` for pending, safely bound promise requests; read [proof responsibilities](references/proofs-and-boundaries.md) for its actual interface. The non-author independently reconstructs obligations, performs each promised substantive step, and records only steps actually checked in exact `scope.proof_steps` with source/KB locators, attempted reasoning and gaps. Fresh evidence enters live KB before a new freeze and explicit plan adoption/prepare. A preparatory snapshot or pending template is not acceptance; never copy labels, manufacture accepted records, edit old snapshots or refresh hashes to conceal missing work.

Keep one canonical authority: formal definitions/results/relations use one label-free `## Canonical statement` with one `latex` block containing all hypotheses, quantifiers and conclusions. Nodes own facts; overview/routes explain; manuscripts own wrappers and reading order. Facets overlap, rather than creating four databases. Navigation edges do not prove implications. New comparisons/deductions require actual reviewed node arguments. New reusable explanations also return to the live KB; review, freeze a new snapshot and explicitly adopt it downstream. Never edit frozen bytes or generated fragments.

## Review obligations before locating them

Read [validation](references/validation.md) and [output review](references/output-review.md). Reconstruct necessary proof/learning obligations from the exact target, reader baseline and mathematics **before** comparing the author's list or locating its entries. Look for missing object identifications, normalization, singular starts, limit topology, regularity and present applications of imported results. Deep theorems may be imported exactly; current substitutions, hypothesis checks and decisive object conversions still require explanation.

Hide long proof interiors and reconstruct the fast route; perform a concrete slow step from declared inputs; change a decisive condition and locate the first failure. Save actual answers/derivations, failures, repairs and unchecked scope. Failure of one proof route alone is not a counterexample. Knowledge-only findings bind existing knowledge-review scope/findings to node/route revisions, hashes and subsections; do not fabricate manuscript locations. Current article findings require obligation_coverage, fast_route_reconstruction, slow_step_reproduction and condition_transfer using existing outcome/finding/locations. Software shape/binding checks cannot judge sufficiency.

`kb validate PROJECT` checks structure. `kb readiness PROJECT --plan PLAN` checks selected scope, closure, sources and promises; accepted fields/source counts do not establish understanding. Keep mathematical, publication, evidence and selection states distinct. Unassessed is not open: openness requires a precise target and dated follow-up searches. Read [records and delivery](references/records-and-delivery.md) for the actual evidence locations. Templates remain pending until actual work. Use `author_reread` for the author's/agent's reading. Other AI tasks may find errors; they do not establish external independent review or real-reader learning.

## Freeze, design and write only requested outputs

`kb freeze PROJECT` fixes immutable bytes, even before readiness; freezing grants no readiness. `kb diff PROJECT --from OLD --to NEW` reports changed knowledge/consumers. Create `output plan PROJECT --output ID --snapshot KB-...` and refine audience, goals, selections, exact proof/import promises and omissions. Read [selection](references/length-and-selection.md) and [profiles](references/editions.md). Overview maps project routes; output outline answers this article's target, audience, principals, points, connections and limits. Use existing plan/outline fields, not an invented API.

`output prepare PROJECT --plan PROJECT/outputs/ID/plan.json` produces exact fragments/materials and an unfinished scaffold. Inspect `artifacts.exposition_design`; knowledge readiness never requires an article outline. Complete topic-specific outline and prose. Reprepare preserves authored main, outline and style. Explicit draft preview remains visibly unverified and retains canonical/material/TeX safety. Missing, extra or changed materials are errors; editable notes belong outside materials.

Follow S0–S5 in [knowledge-to-manuscript](references/knowledge-to-manuscript.md): scope and fixed inputs; read selected fast passages; draft the opening with complete canonical results; open precise slow sections on demand; establish consumed auxiliaries before their first proof use; check closure and final pages. Do not read every slow proof before composing the opening. Conflicting conditions, missing constants/lemmas, promised derivations, nontrivial comparisons and Paper novelty/proof closure require slow/source reading. Missing mathematics returns to live KB, review and a new snapshot, never an invented manuscript fact.

Every mathematical statement environment (including definitions, examples, problems, remarks, conjectures and custom equivalents) keeps its existing type, automatic number and label but has **no descriptive optional title**. Put terminology and exact source/version/locator in adjacent visible prose. Proof-target headings and the supported theorem recall remain allowed. Borrowed, adapted and composite statements need accurate nearby attribution; truly local derivations do not need invented citations. A citation token cannot certify its support. Establish important consumed Lemma/Proposition interfaces before their first proof use, preserving independent branches. Read [introduction](references/introduction.md) and [writing style](references/writing-style.md). Every principal keeps its complete canonical input in a suitable result environment, nearby indispensable definitions and an isolated full-statement reading. Fix canonical deficiencies in the KB before freezing again. Surrounding prose may not strengthen quantifiers, strictness, ranges or status.

Under **r5**, Minimal has no abstract and exactly three numbered mathematical sections: **Main Results / Key Mathematical Ingredients / Connecting the Ingredients**. Every complete principal appears in the first section. The second establishes only consumed, callable ingredients; the third performs each decisive connection with inputs, actual constructions/equations/estimates/limits, output, next consumer and indispensable conditions. References do not count as a fourth section. Subsections are allowed; extra top-level units, front matter summaries and body appendices cannot evade the contract.

Thematic has no abstract: its first section states precise questions and representative full results with common objects and comparison conditions; the body explains real difficulties, methods, mechanisms and supported synthesis. Lecture has no abstract: its first section states learning goals, the full core goal theorem and a faithful proof route; the body teaches every promised construction, computation, proof and first application from declared prerequisites. Neither mode has a fixed section count. Paper retains a concise research abstract and Introduction presenting closest prior work, precise remaining difficulty, complete new results, accurate differences, new idea and proof route; the body closes the proof. Known-result Paper drafts must accurately attribute the known claim rather than invent novelty.

Paper defaults prominently to **DRAFT_UNVERIFIED**; formal research delivery requires authorized contributions, explicit comparison pairs, primary support for closest prior results and complete proofs. Retain F1 body locations, F2 view/design, F3 comparison/support, F4 incomplete-design safety and all four understanding-review duties. The five views integrated/foundations/results/methods/boundaries change reading emphasis, never mode duties or facts. Current Minimal always follows its strict three-section contract; old policies are unsupported and old records are not rewritten. See [profiles](references/editions.md) and [knowledge-to-manuscript mapping](references/knowledge-to-manuscript.md).

Prefer **about 2–3 normal actual typeset lines** for ordinary explanatory prose in all modes. Review longer blocks for hidden objects, conditions and mathematical actions; keep continuous proofs together when the reasoning needs it. Show useful equations, maps, estimates or transformations with nearby meaning; never add decorative formulas, force breaks, shrink type/margins, fragment proofs or omit hypotheses. Necessary complete statements/continuous proofs may exceed the target with a specific justified exception. Record actual PDF page/block, source location, finding, repair or considered alternatives, final PDF hash and reinspection scope. Source-line counts/formula quotas cannot certify readability.

## Build, inspect and report fixed evidence

Run `output validate PROJECT --output ID --stage structure`; actually reread each final TeX version and complete seven whole-manuscript checks plus located mode/principal/step findings. Ordinary findings must point to executed substantive body content, not comments, preamble, uncalled definitions or false branches. Exact bytes alone do not validate surrounding prose.

Run `output build PROJECT --output ID` then `output render PROJECT --output ID`; open **every actual page**. Rendering is not inspection. Repair, rebuild and refresh affected bindings. Preserve failed attempts and prior successful builds. Visual findings apply only to their fixed PDF/images; new pages need new observations and reused unchanged-page findings need verified image identity. Read [layout/build](references/layout-and-build.md).

Run `output validate PROJECT --output ID --stage release`. Only current-r5 `RELEASABLE` outputs can use `output package PROJECT --output ID --to FILE.zip`; reopen the rebuildable archive. Old/unknown policies are unsupported; do not rename them or migrate accepted evidence. Preserve previous snapshots, plans, manuscripts, reviews and PDFs. Explicit `max_pages` is the only hard length gate.

Report software checks, source/mathematical reading, exposition task attempts, actual PDF inspection and real-reader feedback separately, with fixed hashes, failures and unverified scope. Real originality/full research-proof quality stays **NOT VERIFIED** without actual authorized original input and appropriate review. Software publication cannot change that. Use [exposition checks](references/exposition-examples.md) for local writing decisions; current templates and primary sources are the inputs, and historical generated samples are not writing authorities.

For maintenance read [template maintenance](references/template-maintenance.md) and validate assets plus an isolated extracted installation. Survey has no Research Studio bridge, native Studio markers or resident multi-agent scheduler. Daily-use collaboration uses actual available tools and ordinary files with one integration writer.
