# One knowledge authority, four authoring modes

Fast and slow are reading layers within overview, routes and nodes; they are not independent databases or required `fast/`/`slow/` directories. The fast layer explains goal, objects, usable input, chosen construction, decisive operation, output, next use and indispensable conditions. The slow layer performs promised constructions/calculations, checks assumptions, constants, admissibility, topology and limits, and supplies precise external-theorem interfaces. Every important fast arrow has a specific slow subsection; slow passages identify the route and consumer they support.

Definitions, results and verified relations have one canonical statement. Overview explains the project map; plans/outlines select a reader's route; manuscripts own exposition and result environments. A relation is evidence only with source support or an actually reviewed deduction. A route map, long pasted proof, navigation edge or “standard argument” cannot replace the required mathematical action. Deep external theorems may be imported exactly; current substitutions, object identifications and hypothesis checks still need execution.

## Match the reader's promised actions

Use declared reader capabilities, not recognition of a theorem name. Establish bridge-required constructions before use; a supplied lecture may assume earlier lectures that a new reader lacks. Compare quality through why an object is introduced, how it is constructed, whether a decisive computation is performed, its first application and where conditions enter. Do not copy a reference's page count, typography or unspoken prerequisites. Report actual AI reconstruction/reproduction tasks separately from real student feedback.

| Profile | Fast-layer use | Slow-layer use and manuscript responsibility |
|---|---|---|
| Minimal | Select complete results, consumed ingredients and shortest intelligible decisive routes. | No abstract. Main Results gives every complete principal; Key Mathematical Ingredients establishes callable inputs; Connecting the Ingredients executes each decisive connection. Compress routine details without hiding the key reason. |
| Thematic | Build a precise question/method/synthesis map with genuine routes and difficulties. | No abstract. First section states accurate questions and representative complete results with common conventions; body supports mechanisms and comparable-assumption synthesis through actual arguments or reviewed relations. |
| Lecture | Arrange a reader's learning/proof route and explain each object's purpose. | No abstract. First section supplies objectives, full core goal theorem and faithful route; body unfolds promised constructions, calculations, proofs, first uses and boundaries in teaching order. |
| Paper | Organize research position, mechanism and known/original/conjectural/unverified status. | Concise abstract plus Introduction covering prior work, difficulty, complete new claims, differences and proof route; body supports all proofs and prior comparisons. Missing research authorization, novelty evidence or proof closure retains DRAFT_UNVERIFIED. Known-result drafts remain honestly attributed. |

Five views change emphasis, not facts or profile duties. Same-snapshot comparisons retain common statements and boundaries while independently designing the requested articles.

For every requested output, settle concrete audience operations, prerequisites, selected principals, proof treatment, exact required_steps and imported inputs early enough to inform the **first output-specific knowledge review**. Different modes can promise different steps while consuming the same canonical statements. Reviewers reconstruct obligations independently before comparing the supplied list. A profile name, generic mechanism card or copied list of step labels is not this contract or its acceptance.

## Actual file sequence

1. Coordinate the full requested reader/proof promises while reading sources and building paired explanations/canonical nodes. Obtain actual source reading/review. For requested articles, hold the first output-specific critical knowledge/coverage review until all applicable plans' promises are available in steps 2–3; do not consume a first review with generic promises and add a second late-proof review channel. Knowledge-only instead completes its actual knowledge/coverage review without output plans or articles. `kb validate` checks structure; freeze never grants readiness.
2. For requested articles, a preparatory `kb freeze` fixes candidate bytes so `output plan` can create each plan. Authors complete audience, goals, selections, exact proof obligations/imports and outline **before the output-specific knowledge review**, with no manuscript prepare yet. This preparatory snapshot is not the final accepted authoring snapshot.
3. Controller creates the [plan-scoped knowledge review request](proofs-and-boundaries.md) for each authored plan and passes its actual returned paths/fixed inputs within the reviewer's read boundary. A non-author checks actual source/KB arguments and each promised step, records exact checked scope.proof_steps, real findings and gaps in owned candidate evidence, and binds the safe content-addressed promise request. Pending templates do not certify checking. Resolve any mathematical gap in live knowledge with corresponding actual review and renewed coherent plans/requests within the existing allowance; do not weaken the original reader promise.
4. Controller integrates fresh evidence and its safe declared inputs, then `kb freeze` creates a **new** immutable snapshot containing that evidence closure. Explicitly set each yet-unprepared plan's snapshot_id to the returned new identity while retaining its reviewed promises, run readiness, then `output prepare`. The promise projection excludes snapshot_id so this adoption does not generate a false evidence cycle. Never alter old snapshot bytes or hash-refresh old accepted evidence.
5. Prepare copies fixed materials, generated statements/conventions/citations/manifest, and unfinished manuscript/main.tex plus style. Authors read these fast/slow materials and write actual exposition, transformations and proofs. Never hand-edit materials/generated. A reusable explanation or mathematical correction returns to live KB, fresh review, new snapshot and explicit downstream adoption within the task's existing feedback/recheck allowance. Pure transitions/layout need not mechanically rebuild KB. Reprepare preserves authored main/outline/style; explicit draft preview keeps input and TeX safety checks.
6. `output validate --stage structure` and actual non-author whole-manuscript, principal, mode/view and proof-step readings bind current files. Map reader input → precise fast/slow subsections → actual TeX/page → attempted derivation/failure using existing findings. `output build` and `output render` create the actual PDF/images; open every page using the permitted installed [native workflow](layout-and-build.md). Keep failures, repairs, current identities and specific long-block exceptions. No score, field quota or render command replaces mathematics or observation.
7. Current-r4 release checks precede `output package`; independently reopen/rebuild the archive. Explicitly unverified Paper can deliver a visibly marked working TeX/preview PDF while formal package rejection remains a separate expected result. Software installation ZIP, mathematical article package and software GitHub Release are distinct. Old-policy runtime inputs are unsupported and left unchanged.

Use installed CLI help for exact arguments. This sequence cannot bypass validation. If a user's test protocol limits repairs/rounds, all knowledge return, rewriting and rebuilding remain inside that bound.

## Knowledge, Paper Draft and research delivery

`kb readiness` checks fixed source/knowledge/coverage and actual plan proof promises; it no longer makes originality a condition for knowledge READY. `output validate PROJECT --output ID --stage eligibility` separately reports the plan/snapshot research gate: known-result-only Paper is REJECTED for original research, missing authorization/difference/proof evidence is UNVERIFIED, and completed recorded plan requirements yield ELIGIBLE as a candidate only. This mechanical result does not perform an originality audit or authorize release.

A known-result or candidate Paper may be prepared with explicit draft status and previewed under existing input/TeX safety checks. The visible bold `Paper Draft -- DRAFT_UNVERIFIED` notice must precede the first section; a placeholder mentioning draft status is insufficient. Setting `draft:false` cannot bypass the independent research eligibility/notice gate. Formal prepare requires both knowledge READY and research candidate eligibility. Formal release additionally rereads current bound contribution findings, actual authorization/prior-art checks, complete proof obligations, manuscript semantics, build and all pages. The existing human contribution-review gate remains mandatory; neither a profile name, a hash nor an ELIGIBLE plan supplies it. Draft manuscript compilation is preview evidence and never formal release acceptance.
