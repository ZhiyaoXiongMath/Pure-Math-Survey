## 1. 本版要完成什么

**给定明确版本的数学论文或有限材料，一次提取可复用的核心知识，用这些相同的内容建立轻量知识库，并按照 `rules.v22.txt` 写出 Minimal。**

唯一公开写作模式为 `minimal`。Thematic、Lecture、Paper 暂时下线；只建库仍是允许的任务终点，TeX-only 是交付格式选项，都不构成新的写作模式。默认生成一份英文 Minimal 和其知识库；用户明确指定语言、范围、格式或只建库时，服从实际任务。

运行采用当前会话及其当前模型，不强制指定模型、推理档位、控制台、子聊天或额外代理。一次抽取和一次成文是两项工作，不承诺只需一次底层 API 调用；长来源可按实际需要分段读取。

## 4. 最短运行路径

### 4.1 默认过程

1. **确定任务和来源。** 固定来源版本、范围、读者及交付格式；已有信息充分时直接开始。默认只读指定来源，引用工具仅在当前接口确需澄清时定点查找。
2. **一次抽取并写入 KB。** 保存核心概念、全部范围内主贡献、必要第二层模块及方法，建立实际模块连接。把必要原文定位随抽取写入，不另补证据报告。
3. **直接组织 Minimal。** 正式陈述从 KB 原字节导出；只创作需要的引导、连接、图标签和阅读顺序。发现数学内容需改，回写对应单元，再导出受影响部分。
4. **构建并交付。** 运行结构和引用完整性的机械检查；默认编译 PDF，记录正文页数。交付 KB、TeX、TikZ、PDF 和短运行记录。只建库到第 2 步结束。

没有审核/批准节点，没有必须创建的其他会话，没有先生成长文再重新抽库。对于单篇材料，默认一名执行者完成；批处理将来可逐篇复用该过程，本版不开发调度服务。

### 4.2 机械检查的有限责任

程序可以检查：JSON 形状、ID 唯一与引用存在、路径安全、所需定义可解析、声明选中单元存在、已导出陈述与 KB 字节一致、TeX 是否编译、引文和交叉引用是否解析、正文页数是否不超过 6。

程序不能仅凭这些检查宣布数学正确、逻辑已证明、所有重要贡献无遗漏或图的数学含义已审核。“有来源定位”也不等于独立证明。

### 4.3 避免返工失控

默认一次成文和一次构建流程；一次构建流程可包含 LaTeX/BibTeX 为交叉引用所需的确定性多遍编译。出现具体错误后，允许至多两轮针对错误或超页的局部修复；每轮只打开受影响信息。仍未满足时交付现有成果并说明精确阻碍，不自动增开审核、扩大搜索或继续循环。

六页无法容纳固定覆盖时，先合并内部支撑、删除重复表述、改正不合理分页；仍不够，明确报告未满足六页合同。不得缩字号、减边距、删掉主贡献后声称合格，也不得擅自拆成多篇规避上限。

## 5. 知识库：同一内容的较小数学单元

### 5.1 粒度

用户所说“把 minimal 再拆成更小单元”适合作为内容标准：每个单元对应文章中真正有用的一项定义、结果或完整模块，不按 PDF 段落机械切割。实现顺序采用**先形成这些单元，再组合文章**，省去第二次抽取。

结果单元本地写明对象、条件、量词、控制关系和结论；允许引用已经精确定义的概念名称。共享记号不能隐藏紧致性、边界条件、正性或正则性假设。模块内部证明默认封装，只补理解路线确有必要的机制。

方法通常是一条模块的简短“方法与用途”。只有具有独立复用价值时才成为独立方法单元；方法名称本身不被包装为一个数学定理。来源中的必要例子、反例、限制可成单元，但不增加外部反例搜索任务。

### 5.2 沿用现有存储方法，减少字段

保留现有 **Markdown + JSON frontmatter + 单一 `Canonical statement` LaTeX 块** 的做法，不更换数据库引擎。继续使用 `N-`、`S-` 稳定 ID；文章自动编号与来源原编号均不充当稳定 ID。

建议并固定如下最小布局（名称可在对应 PR 中作有理由的局部调整，语义不变）：

| 路径 | 权威内容 |
| --- | --- |
| `project.json`、`scope.md` | 合同身份、任务、范围、来源入口；不复制所有数学内容 |
| `knowledge/sources/S-*.json` | 来源题名、作者、版本、URL/本地引用、引文键、已知的原始文件 hash |
| `knowledge/conventions.tex` | 真正共用的宏、稳定记号、算子约定；不藏全局数学假设 |
| `knowledge/nodes/N-*.md` | 每个数学单元的唯一正式内容 |
| `knowledge/routes.json` | 主要组合及短连接文字；不包含重复的完整定理 |
| `knowledge/index.md` | 程序生成的简短导航；无第二篇 overview |
| `outputs/minimal/plan.json` | 选中节点、三节的顺序、图中节点/部分映射、格式；不再含审核或证明承诺账本 |
| `outputs/minimal/generated/` | 从 KB 导出的陈述、引文及宏；只允许重生成 |
| `outputs/minimal/manuscript/` | `main.tex`、`architecture_graph.tex` 及必要连接排版 |
| `outputs/minimal/build/` | PDF 与实际构建日志 |
| `run.json` | 单一、简短运行事实记录 |

`knowledge/overview.md`、`discovery.md`、`coverage.json`、fast/slow 成对文本、`evidence/reviews/`、强制 snapshot 不再是新项目必需项。无必要时不创建空壳替代品。可保留一个自动生成的输入 hash 清单用于更新与可复现，不把它提升为审批手续。

### 5.3 单元最小字段

| 字段 | 要求 |
| --- | --- |
| `schema_version`, `id`, `kind`, `title` | `kind` 为 definition / result / method / example；title 供检索，不进入带描述性名称的定理标题 |
| `role` | principal / ingredient / bridge / context / boundary；是当前整理任务中的作用 |
| `sources` | 每项有 source_id、真实 locator；原编号和版本由此追溯 |
| `definition_refs` | 实际需要的概念单元 ID；已定义术语不能只是无定位的文字 |
| `source_status` | stated / extracted / imported / unresolved；描述来源关系，不表示已独立证明 |
| `importance` | level 为 1–5 或 null；status 为 proposed / human_supplied / unassigned；reason 简短且可空；标明是候选或真实人工输入 |
| `Canonical statement` | definition / result 以及作为正式例子展示的单元必需；只保存一份完整 LaTeX 数学正文，无 wrapper、label 或自编定理标题 |
| `Method and use` | 需要时用一小段说明方法身份、关键作用、下游用途；不要求内部证明 |

对于一个方法单元，若没有独立数学陈述，正文可只记录对象、操作思想、适用条件、实际用途及来源；它不能因此成为声称结论的图节点。`statement_kind` 如需区分 theorem/lemma/proposition/corollary/example，可作为一个短元数据字段，由模板包裹正文。

不要同时在 frontmatter 重写一套完整 assumptions/conclusions，又在 canonical 块重复同一个定理。若后续需要结构化打分输入，应从权威内容导出，不把双份数学正文引入当前版本。来源没有明确的版本文字时，以实际提供的固定文件及其 hash 固定内容身份，版本描述标 unknown；不能编造 v2、出版年份或全文已读记录。

### 5.4 三个维度分别保存

**类型、论文内作用/展示深度、领域重要性是不同信息。** 重要性不由 Theorem/Lemma 名字、证明顺序、引用频次、困难度或图中纵坐标自动产生。依据：转写 01:20:59–01:21:36 与 rules #016。

1–5 级只是可用的标注空间，并非要求五层全部展开。明确时可给一个候选等级及一句理由；不确定时填 null。重点产出可读、可分级的知识内容，未知等级不阻塞运行。候选等级不当作人工训练真值，用户以后的打分试验另行开展。

### 5.5 关系与组合

一个关系记录回答：哪些上游输出，被用于满足哪个下游条件，还需要哪些实际假设。采用一个 routes 表，不再让每个 node 复制同一组 proof edges。

每条组合至少包含：`id`、`premise_sets`、`target`、`mapping`、`source_locator`、`status`。`premise_sets` 中一个集合内为共同所需，多个集合为可替代途径；每个集合各自附 `additional_inputs`。例如 `{A,B}+H -> C` 与 `{D}+K -> C` 是两条充分路线，不能画成 A、B、D 全部同时必须。

`mapping` 只写简短数学对应：“A 的哪个输出满足 C 的哪项要求”；范围、正则性、量词或一致性改变后不能省略必要转换。没有来源支持的连接记 unresolved，不能以实线证明箭头进入读者图。若缺的是主路线必须的连接，运行结果标为 incomplete 并指出，不另起证明项目。

文章第 3 节的连接可直接使用关系记录中的短文本；图使用同一 IDs 和关系。并行路线、方法说明、主题相关各按实际意义呈现，不强加蕴含箭头。组合层一般只保存主要 5–10 阶段尺度，不递归收录模块内部调用。

### 5.6 单元导出、更新与多篇积累

独立导出一个结果时，程序附带实际依赖的定义、记号约定和来源信息；只写“见本篇开头”不够。原文编号留作来源，输出文稿另用自动编号。定义引用缺失或循环错误给出具体诊断。

修改数学陈述应在 live KB 完成，更新后重生成相关片段及文章；禁止仅改 generated 文件或在正文手抄一份修正版。旧输出保留明确版本，不静默覆写此前交付。相同来源重复运行可复用未变的内容，检查任务和文件身份后只处理变更，不全量重新抽取。

多篇材料可按来源/项目分目录积累稳定单元，本版不自动判断两个不同陈述“数学等价”并合并。需要时通过显式来源引用建立关联，避免错误去重。

## 6. Minimal 的具体成文合同

仍使用用户已接受、也与当前仓库吻合的三节骨架：

1. **Main Results**：先建立必要的核心概念和稳定记号；呈现范围内全部独立主要贡献，准确注明不同分支的条件与结论。不是只选择一个主定理。
2. **Key Mathematical Ingredients**：选择能解释主路线的少量完整模块；保留真实假设、重要输出、方法身份与后续用途。源文章中的多个内部事实可以封装成一个有来源支持的模块。
3. **Connecting the Ingredients**：短而具体地说明输出如何满足下一步输入，并区分共同前提、平行结论、替代路线；配一幅与正式陈述一致的可编辑图。需要时可用小节，但不扩成第四节内部证明。

三节是组织骨架，节内的选择和次序服从实际数学依赖。无摘要、额外前言或正文附录；运行记录不进入读者文章。概念复杂并不意味着应藏在最后；一个深工具也可以作为完整第二层模块使用。任何选中的完整结果都不得靠“采用前面的假设”省略本地数学条件。

### 6.1 陈述与来源

- 数学环境自动按节编号，必要时共享计数器；Theorem、Proposition、Lemma、Definition、Example、Problem 等均不加描述性可选标题。
- 结果所借用、改写或合成的来源放在相邻可见文字中，并与标题/开头保持同页；不能让 citation 代替条件和结论。
- 术语已被精确定义后直接使用。例如原文围绕某个正性概念组织结论，先定义它，后续用术语表达；不在每个陈述反复展开完整定义。
- 控制方程、关键关系、真正用于连接的决定性输出适当独立展示；常规提及留在行内。无需机械满足每段行数配额。
- 本节按 rules #002–#003、#006、#019–#027、#052–#068、#083–#089 实施，不沿用旧 r5 要求慢层完全复现所有承诺推导的做法。

### 6.2 排版与产物

正文、题名与图合计最多 **6 页**，参考文献另起页且不计入正文上限。正文与正式陈述 **11pt**，图中实质文字基础字号至少 **10.5pt**，单栏、正常行距、边距至少 **20mm**。不能用整体缩图、负间距、压行距或缩字号达标。

图放在 `architecture_graph.tex` 并由 main 引入，采用 TikZ 或可等价编辑的矢量形式；图的结果节点能定位到正文编号或具体分项。方法注释有明确归属，不能仅靠距离猜测，也不为一条注释虚构依赖。

段落、正式陈述、分项、独立公式、节标题应有稳定的间距层级。run-in 小标题上方可留适当空白，与解释紧邻。长陈述可自然跨页，不重复标题，不加无必要的 continued。参考文献前显式换页，并记录正文的实际末页。

## 7. 产物与状态

| 请求 | 默认产物 |
| --- | --- |
| 只建库 | project/scope、sources、conventions、nodes、routes、短 index、run.json |
| Minimal | 上述 KB + main.tex + architecture_graph.tex + 实际使用的 bib/style/片段 + main.pdf + 构建日志 |
| 明确 TeX-only | 同样的数学内容及可重建 TeX/TikZ/bib；PDF 缺省，页数状态标 not_measured |

`run.json` 只保留：版本身份、来源 IDs/版本、实际输出路径、KB 输入摘要 hash、结果为 complete / incomplete / failed、已知限制、PDF 构建状态、main_pages/total_pages、实际耗时、可取得的 token 数及计量方式。缺少 token 接口时为 null，并标 unavailable；不估成“已节省 X%”。

complete 表示所请求产物在该合同下已生成，不表示数学已认证。对于未编译的 TeX-only，不能声称实际六页已经验证；对于编译失败或超页，不能把 PDF 标为达标。正常交付说明简短，不把内部状态代码和审核话术塞进读者文章。

## 8. 轻量化的可执行约束

- SKILL 入口只含范围、流程、必读指针、错误边界。它不复述全部 100 条规则。
- 原始 rules 在需要写 Minimal 时读一次；只建库只读简短 KB 合同，不被迫加载排版规则、开发文档或历史报告。
- 标准新项目不加载其他模式、dispatch、review、proof-obligation 的指令文件；禁止从旧引用链绕回来。
- 来源元数据、数学陈述、模块连接分别只写一次；Markdown/TeX/图的派生视图尽量程序生成。
- 无强制后台代理、无审核轮次、无全局文献查新、无每次重建全库、无同一个问题的多份长报告。
- 需要读原文证明片段时只读足以识别模块/桥梁的部分，不为减 token 捏造未读内容。
- 用户纠错只修相应单元、连接和输出；不默认重新梳理全篇。

不承诺理论上最小 token。验收应比较同一来源、范围、交付格式和模型下的实际轨迹；区分一次性开发消耗与以后每篇论文的运行消耗。

## 10. 旧项目及下线模式

2.4.1 默认只支持新合同。旧 KB/output 不能仅改 schema 字符串就当新数据。识别旧项目后给出明确 `LEGACY_PROJECT_UNSUPPORTED`，不写入任何原文件；用户可保留相应旧安装处理旧项目，或在新目录重新提取。**自动迁移器不在本版范围内。**

Thematic/Lecture/Paper，以及旧 views 的 foundations/results/methods/boundaries 参数返回明确 unsupported；`integrated` 可作为固定兼容别名接收，但不再公开五视图选择器。用户明确请求禁用模式时不能偷偷改成 minimal。自然语言 `mimimal` 的明显拼写错误可解释为 minimal；CLI 规范拼写仍为 `minimal`。

旧模式可留在 Git 历史中；如确需仓库历史资料，必须在安装树之外并明确 historical。历史产物和证据不改写。README 和新开发入口都指向本版当前规范，旧 STATUS 只加历史/新入口指针，不维护两份当前进度。

## 11. 最少但有效的验收

开发期检查只覆盖真实风险，不为每条规则编一项软件测试，不在每次运行重做这张表。

| 验收 | 证据 |
| --- | --- |
| 只保留 minimal | 新安装入口/元数据/CLI/资源一致；禁用模式与旧项目被拒绝且无文件变动 |
| 无运行审核 | 无 reviewer 调度、无 review 文件依赖；KB → prepare → build → package 在不存在审核记录时完成 |
| 同源 KB | 一条 canonical 改动能传到正文；重复 prepare 不覆盖作者引导文字；独立导出附必要定义 |
| 正确表达关系形状 | 小型合成数据覆盖共同前提、备选路线、独立分支、缺失引用；不把结构测试说成数学证明 |
| rules 样例 | 一篇固定来源的实际 Minimal + KB，主贡献/概念/关键模块对齐；一次有限开发验收，保留来源版本 |
| 版式 | 代表样例编译成功，正文≤6页，参考文献新页；开发时看最终页面检验模板，不建立用户运行审核员 |
| 发行 | 实际安装 ZIP 与源码一致；Linux/Windows 现有受影响检查及干净目录安装可用 |
| 成本 | 记录实际模型、范围、格式、耗时、可得 token 和默认加载资源；不可得数值留空 |

实际样例优先复用已有合法材料；如没有适合的新样例，选公开主来源并记录固定版本。当前交付不包含论文 PDF，因此不得将本指南写成已完成某篇论文的实测。本版不以跑完 50/500 篇作为发布前提。

如果有可比的旧版测量，报告实测差异；只有旧记录而条件不同，明确不可直接比较。不能为了填基准表再跑一套昂贵旧审核链，也不能用文件字节数冒充 token。
