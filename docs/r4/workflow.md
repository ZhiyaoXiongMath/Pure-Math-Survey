The installed entrypoint is skills/pure-math-survey/SKILL.md. Its calling human chat is controller; trusted role=worker tasks follow the worker resource and never recursively dispatch. These are installed resources; private development guides are unnecessary for daily use.

The installation supports only policy four-modes-2026-10-13-r4: strict Minimal three sections, no abstract in Minimal/Thematic/Lecture, and a concise Paper abstract. F1–F4 and all four understanding duties remain required. Software is 2.1.0, knowledge/snapshots are schema 2.0.0, and outputs/policy-bearing reviews are schema 2.2.0. Explicit obsolete or unknown output contracts are rejected without rewriting their files; no historical template, recorded-policy processing or migration path is provided. Historical evidence remains recoverable for its original version.

Dispatch carries the exact permitted installation, original-source and output paths and the actual human/task read boundary. Workers check that boundary before loading auxiliary workflow instructions: a ban on the global same-named skill differs from a ban on all global skills. The installed references/layout-and-build.md supplies source extraction, build/render, actual full-page inspection and package rebuilding instructions within the supplied resources.

Coordinate every requested output's reader and detailed proof promises before its first output-specific knowledge review. The controller creates an authored current plan and a pending mathematical review request with `review template --plan`, and passes its returned content-addressed request path to the nonauthor. A template has empty checked-step scope and no acceptance. The reviewer reads the actual bound knowledge/source arguments and promised operations, records only genuinely checked exact steps and gaps, and writes isolated candidate evidence. The controller integrates fresh evidence and safe declared inputs, freezes a new snapshot, explicitly adopts it in the yet-unprepared plan without changing reviewed promises, and then prepares and writes the article. Old snapshots and accepted records are never rewritten or hash-refreshed. A finite task's existing feedback allowance also covers this coordination; late promises do not create another revision channel.

Local dispatch-ledger tests cover bookkeeping exceptions and author separation. They do not create chats, verify human authorization, inspect real model configuration or accept mathematics. Real normal-path product dispatch requires installed controller/worker tool receipts and actual artifacts; this implementation note does not claim that execution took place.

It requires the single current schema-policy contract and actual execution of current policy, workflow-binding and dispatch regressions. The smoke path leaves real generation unexecuted; old-example verifiers and flags are removed. See current tool help for the manifest contract. Mathematical reading and actual new-PDF inspection require their separate evidence. Private test-round requirements remain in the testing task, not the generic product's permanent policy.

Old generated examples and reference samples are absent from the current installation. Historical documentation records prior evidence only for its original bytes, recoverable in Git history. Independent generation, source reading, paired knowledge review, manuscript duties, real TeX logs, all PDF pages and applicable unpack/rebuild checks need their own current evidence. True originality, external peer review and real-reader learning remain unverified without those actual activities.
